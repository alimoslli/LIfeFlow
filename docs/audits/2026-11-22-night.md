## Verified safe (traced, not assumed)
- **Waitlist gate.** `getSessionUser` returns null for a waiting person (current-user.ts:40-44), so every API using it answers 401, and
  `requireUser`/`withCurrentUser`/`mutate` redirect to /waitlist. The only doors that see them are `getAccountUser` (waitlist
  actions, export, passkeys, Apple/Google link start) and `account: true` (settings profile/security/data, `auth.*`,
  `profile.update`, `ai.consent`): all account-scoped. Session-free doors (SMS, inbound email, crons, Apple Health) go through
  `appOpenFor`/`openToApp`. The layout path check uses `x-lf-path` set by proxy.ts, which a browser cannot supply. Removing the old
  `setUp` exemption (current-user.ts) means a person mid-setup is now also gated when the switch is on; that is intended.
- **Under-13 from the waitlist.** `saveWaitlistBirthday` (waitlist/actions.ts:56) uses `getAccountUser` (null when locked), takes
  `lockQueue` before the row lock and calls `saveBirthday` -> `blockUnderAge`; an account still in setup locks at once, a
  finished one is read the date back first (onboarding.ts:282-305). `after(afterAgeLock)` runs only when the lock committed.
- **Gmail filing.** Morning slot only, and only with `emailFilingOn && aiAllowed(prefs) && !opts.idle` (engine.ts:251); the notify
  cron skips age-locked, suspended and demo accounts and non-open accounts. Content is untrusted: sender must pass the topmost
  mx.google.com Authentication-Results (email-auth.ts), then the strict extraction, `door: "gmail_filing"` through the AI gate.
- **purchaseMarks under the Money lock.** Both `dayClockData` callers pass `money: !locked`; with the lock on, the whole purchase
  block, `spentByDay` and the "came in" recap line are skipped (day-clock.ts:198-281, 450). Email finds that are money kinds are
  filtered (sky-insights.ts:93,175).
- **Google optional permission.** Only `calendar.calendarlist.readonly` is exempted (google.ts:128); Gmail and Calendar are still
  required; `needsCalendarList` drives the reconnect note.
- **AI Lab room.** Migration 0073 is idempotent, `when` 1799200000000 is above 0072; no user data, no new action or page.
- **Uncovered area picked: unauthenticated and webhook doors** (`/api/errors`, `/api/inbox/email`, `/api/sms/inbound`,
  `/api/offline/replay`). Errors: same-origin, 30/h per IP, scrubbed. Email: shared secret, drop-unknown, drop-waiting. SMS:
  Twilio signature, per-number limit, claimed before work, locked/suspended/waiting get no answer. Replay: session, same-origin,
  account-bound. No findings.

## Findings

### 1. Exam-aware free time was applied to only two callers (Medium, fix now: wrong advice)
`busyAgenda` (calendar.ts:476) makes timed exams block time, but other free-time finders still call `getAgenda`, where an
assignment never blocks (calendar.ts:396,417). Failure scenario: a student has a 10:00 exam. The proactive "study block before a
shift" (detectors.ts:209-210, 120-minute slot), the habit slot for tomorrow (reviews.ts:370-373) and the briefing's free
minutes per day (briefing/collect.ts:20-34) still count the exam hours as free, so Today can say "free 9 to 11" or propose a block
over the exam: the same bug the AI Lab found for the skyling's tool. Also `findConflicts` callers (calendar/plan pages,
overview.ts:45, briefing/rules.ts:54) show no clash between an exam and an event booked on top of it. Fix: route these through
`busyAgenda` (plus a test per caller).

### 2. A morning slot spent while idle is not retried when the person opens the app (Low, fix now)
`runSlot` logs `slot:<day>:morning` before the idle check (engine.ts:240-251). If the cron runs for an account that counts as
idle, the slot is consumed, so opening the app that morning does not file Gmail until tomorrow. No overspend, only a missed
look. Fix: skip the log row, or run the filing only after the idle check decided.

### 3. A bill email filed as a plain task can name an amount under the Money lock (Low, fix now)
`emailFinds` marks money only for the listed kinds or a "Reminder: pay " label (sky-insights.ts:93). A task or event find whose
label came from a bill email (for example "Rent due, $950") shows its label on the sky while Money is locked. Fix: also use
`namesAmount` on the label, as `fromMessage` already does (line 134).

### 4. Verification gap (Info, needs owner)
The build needs network for Google Fonts, so a cloud audit chat cannot run the e2e suite or the phone walk. Self-hosting the two
fonts (or a build flag) would let QA verify UI changes. Owner's choice (a change to how the build works).

No other issues found on the surfaces above.
