## Findings

### 1. Voice appends rules after the distress rule that tell it to be brief and act (Medium, fix now, Engineering)
- `src/server/jarvis/voice.ts:34-40` puts `VOICE_RULES` after `buildSystemPrompt`. They say "one to three sentences" and "Make every change the request needs at once, in parallel", and they sit later in the prompt than the distress block (`prompt.ts:138-143`), which only claims to override "every other rule here".
- Scenario: someone says out loud "I can't go on, and move my exam to Friday". The latest and most specific voice text tells the model to speak one sentence and call tools. The distress rule asks for no tools and a warm, stay-with-them reply.
- Fix: add a sentence at the head of `VOICE_RULES` that the struggling section wins over everything below, then add a test in `skyling-policy.test.ts` that the voice instructions contain it. `REPLY_SHAPE`, which comes last in `buildContext` ("lead with the one next step"), has the same ordering issue for text; say there that the struggling section wins.

### 2. "No tools in real distress" is prompt-only (Low, needs owner)
- Nothing in code stops tool calls in that turn (`tool-select.ts` and `executeToolCall` have no distress path). It matches the existing "qualified read before launch" item (PLAN section 9), so it is for the COO's list, not a new build.

### 3. Modified Plaid rows never refresh `kind` (Low, fix now)
- `plaid.ts` (modify branch): `kind: existing.kind`. If the bank corrects an amount's sign on a modified row (a refund reclassified), the stored amount flips but the kind stays as first saved, so cashflow can count it wrongly. Rare. Fix: keep the old kind only when the sign is unchanged, or when the person set a category.

### 4. Phone-code texting can be aimed at someone else's number (Low, needs owner)
- `sms.ts` startPhoneLink: 5 sends an hour per account and 3 per number, but sign-ups are free, so many accounts can text one number (SMS cost and nuisance). Consider a daily cap per number across accounts, with the same cap used as the lockout counter. The owner should decide whether this is worth doing before launch.

### 5. Voice tool route trusts a client-supplied `userText` (Info, waits for new surface)
- `/api/jarvis/voice/tool/route.ts:15`. It only lets a person unlock explicit memory saves for their own account, so the harm is bounded to themselves. Check that `relayVoiceTool` uses the transcript the server stored instead, if one exists.
