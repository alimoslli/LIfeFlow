# Desktop e2e on main: what was wrong, and what is still open (2026-11-11)

Owner's question: "What's wrong with the main desktop tests?"

## Answer

Nothing in main's code. The four failures the COO reported earlier came from the COO's own worktrees, whose `node_modules` was a symlink to another checkout:

- the landing page's "See what it does" link;
- the onboarding name box under 44 px;
- two birthday cards on Today.

On a clean install and build of `origin/main` (d7e93ff0), all 72 desktop tests pass.

## Evidence

| Check | Result |

## What changed

- **`tests/e2e/global-setup.ts`**: a guard. Before touching the database, it reads `.next/static`. If the CSS has none of `.min-h-11{`, `.h-10{` or `.max-lg\:hidden{`, it stops with a message that gives the fix.
  - Throws the message: a folder with no build, a folder with only stale CSS, and the symlinked build.
  - Passes: the clean build.
- **`CLAUDE.md`** (Dev gotchas): a worktree needs its own `npm ci`. Never symlink `node_modules`. Before an e2e run: `rm -rf .next && npm ci && npm run build`.
- **Three test fixes** from the independent review (below):
  - `timeline-labels.spec.ts`: the night cases set the browser clock in the runner's time zone, but the account is in America/New_York. On a UTC runner, "1:05 AM" showed 8:05 PM the evening before, so the night case never ran at night. They now use the account's zone, as the 9:30 PM case already did. Passes on a UTC runner (17 of 17 with the two files below) and on a New York runner (8 of 8).
  - `onboarding.spec.ts`: the "today" birthday was typed as the UTC date. For a browser west of UTC in the evening, that date is already tomorrow. It now uses the local date.
  - `perf.spec.ts`: its seed ignored `E2E_DATABASE_URL`. It now uses it, like the other specs.

## Final gate (the pushed state)

- Full desktop project: 72 passed in 8.0 min.
- `npm run check`: typecheck, lint and format clean; 190 test files, 1,490 tests passed.

## Still open (not fixed here)

None of these fails today. Each one can hide a bug or go red under load. They are for a builder, one at a time.

1. `hq-cards.spec.ts:155-157`: waits a fixed 16 s, then checks that items remain. Nothing proves the 15 s refresh ran.
2. `hq-desk.spec.ts:162-170`: every room reads Asleep, because the seed empties `hq_chats`. The night rule is never exercised.
3. `hq.spec.ts:184`: `/^Open the .*decision|^Nothing needs you/` is satisfied by "Nothing needs you" alone, so the decision link is never checked.
4. `hq-live.spec.ts:38,47,82,96`: expects "2 min ago" and "12 min ago" for seeded rows. `right-now.tsx` rounds to the nearest minute, so a render about 30 s late reads "3 min ago" and fails.
5. `perf.spec.ts:11-12,63-67`: wall-clock limits (3 s and 0.6 s) that fail under load. Playbook item 9 requires them, so they stay. Run them on a quiet machine.
6. `global-setup.ts`: empties only `users` and `rate_limit_buckets`. Other tables carry over between files: `announcements`, `error_reports`, `hq_settings`, `hq_files`, `job_locks`, `app_access` and `sms_inbound`. For example, `hq-marketing.spec.ts` leaves `hq_settings` values that `hq.spec.ts` runs with. No test reads them today.
7. `timeline-labels.spec.ts:16-58,65`: when no words are measured, `problems()` returns an empty list, and no test checks the count. A screen with no words would pass.
8. `promises.spec.ts:20-21`: the pattern also matches the "Yes, I did it" button that was just tapped. The database check below it does cover the outcome.
9. `admin.spec.ts:46`: the check that feedback was sent is loose. The database check on line 48 covers the outcome.
10. `admin.spec.ts:56-64`: if the test fails between publish and "End now", a live announcement is left behind.
11. `assistant-name.spec.ts:88`: one missed `isVisible()` check ends the tour loop early, so the later steps aren't checked.
12. `core.spec.ts:71,81`: one check fails to catch a problem if the message's wording changes, and one count is read before the page has settled.
13. `onboarding.spec.ts:50`: if the Google link is missing, the check is skipped instead of failing.
14. `companion.spec.ts:49-51,77`: the "no React #418" check only listens for `pageerror`. React 19 can report hydration mismatches as recoverable errors, which may never reach it. Not verified either way.
15. Phone-sized tests in desktop-named files also run in the desktop project. This is harmless.

Checked and not a risk:
- the authenticator-code test (the server allows one 30 s step either way and blocks reuse);
- the Stop test;
- the UTC date in `hq-marketing.spec.ts` (the server uses UTC there too);
- `companion.spec.ts` (it pins New York time);
- `celebration.spec.ts:49`.
