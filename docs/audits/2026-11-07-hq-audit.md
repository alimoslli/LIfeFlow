# HQ audit, 2026-11-07

Fresh-eyes audit of LifeFlow HQ (`/admin/hq`, Marketing, Settings controls, the company layer), the Work page's pay tiles, and one extra area: the Work page flows (add a job, record a paycheck, where a paycheck goes). Earlier audits covered the app (11-05) and Gmail duplicates (11-06), so the Work flows were not covered.

Method: read the code, then drove a production build against the e2e database with the fake OpenAI server, using throwaway accounts (one admin with 2-step set the way the e2e specs do, one normal user holding a planted name and email to look for leaks). Phone 390x844 and web 1280. No live site, no real account, no paid key. The existing `hq-phone`, `hq-marketing-phone` and `hq-cards` e2e specs also pass (4 of 4) on desktop and the iPhone profile.

## Summary

HQ is in good shape. Every admin page and every admin action calls `requireAdmin()`. A signed-in non-admin gets a 404 on every `/admin` page and the export route. The four `/api/hq/*` routes refuse a missing, wrongly shaped or unknown key (401). Decision cards refuse every missing field and name it. Nothing in HQ leaked per-user content (only account name and email, which ADR 0022 allows). No horizontal scroll or overlapping controls on 25 admin pages at both widths. No "Jarvis" or model names on public pages or admin pages (admin pages do say "OpenAI" in the owner-only App and Activity panels, which is fine for the owner).

The Work page has **no "Est. gross" tiles any more** (removed in `be99e22`). It shows paid hours only, which is what the Money rule needs. No finding there.

There are 2 fix-now findings (both in how forms show errors) and 2 needs-owner items. Nothing waits for the new surface.

## Findings

### H1. fix now (medium): forms show raw validation text with internal field names
- Evidence: `src/server/actions.ts:31-36` (`messageOf` builds `"<field>: <zod message>"`). Screenshot `docs/audits/shots/2026-11-07/phone-work-paycheck.png` shows the red box "hours: Too small: expected number to be >=0". Typing "abc" in Net pay gives "netCents: Too small: expected number to be >=0".
- Why: every form built on `mutate` (Work, and all the others) can show code words to a person. That breaks the playbook voice rule (plain, no tech talk) and the CLAUDE.md rule that users never see internals.
- Smallest fix: in `messageOf`, don't print the path or Zod's wording. Map the usual cases to plain text ("Enter a number of 0 or more", "Enter a date", "This one is required") by issue code, falling back to "Check what you entered and try again." Add a unit test that no message contains a camelCase field name or "expected".

### H2. fix now (low-medium): a form that fails clears what the person typed
- Evidence: same screenshot. Net pay was filled with 412.30 and Hours with -4; after the failed save, Net pay is empty again and the browser says "Please fill out this field". Cause: React 19 resets an uncontrolled form after every action, success or not (`src/components/action-form.tsx:59-71`, which only resets by hand on success).
- Why: a person who mistypes one box loses the others. Seen on the Work paycheck form; the shared `ActionForm` means other forms behave the same (I only checked this one).
- Smallest fix: in `ActionForm`, on a failed result (`!r.ok`) put the submitted values back (keep a ref to the `FormData` and restore it), or switch to `onSubmit` with `preventDefault` and call the action inside `startTransition`, so React doesn't reset. Add an e2e step to the Work paycheck test.

### H3. needs owner: "Record a paycheck" asks for money to be typed and nothing reads it
- Evidence: `src/app/(app)/work/page.tsx:167-215` (the form) and `addPaycheck` in `src/server/services/work.ts:437-444`. A search of `src` shows `paychecks` is read only by the Work list, the data export and the assistant's work tool; the forecast, Today and Money never use it (`expectedPay` in `forecast.ts:200` works from bank deposits and tracked bills).
- Why: CLAUDE.md says never ask people to type money in, and the card is titled "Actual pay, as you record it". A paycheck typed here also isn't matched with the bank deposit, so it could be double-entered later. It is optional and not a nudge, so I did not call it a rule break.
- Smallest fix (needs a yes, since it removes a feature): either remove the form and show deposits that Plaid tagged as pay, or keep it and say it is only a note. Options for the yes or no list.

### H4. needs owner (low): signed-out visitors get a redirect, not a 404, on `/admin/*`
- Evidence: anonymous requests to `/admin`, `/admin/hq/settings`, `/admin/users/export` and `/admin/hq/files/<id>` all return 307 (to sign in) from `proxy.ts`. A signed-in non-admin gets 404. ADR 0022 says "anyone else gets a 404".
- Why: it says the path exists, though every protected path behaves the same way, so it reveals little.
- Smallest fix: have the proxy let `/admin` through to the page when signed out, so `requireAdmin()` returns the 404. Skip if the owner is fine with the redirect.

## What works (checked, no action)
- **Admin guard:** 17 of 17 HQ actions and 10 of 10 admin actions start with `requireAdmin()`; every admin page does; `files/[id]` and `key-seen` return 404 to non-admins; the CSV export uses `adminFor` and 404s.
- **Scripts API:** `/api/hq/inbox`, `errors`, `report` and `files` return 401 with no key, a malformed key, and a well-formed unknown key. With a valid key they work. Error groups come back wrapped as untrusted data.
- **Decision cards:** missing fields are refused with a plain list; blank-space fields count as missing; more than 5 change lines, a bad effort value and a made-up picture id are each refused (`services/hq.ts:202-260`, `1150+`). A card with an empty "Send changes" note is refused in `decideApproval`.
- **Settings controls:** autonomy, round switches, credit budget (0 to 10000, whole number, server checked) and the three delegations save and persist. "Never decided without you" lists match `docs/hq/company.md`.
- **Privacy:** People, Feedback and Announcements pages show accounts only; no content from the planted user's account appeared anywhere in admin.
- **Look:** no sideways scroll, no overlapping controls (checked by geometry on 25 pages x 2 widths), cards and Settings read cleanly. Screenshots: `shots/2026-11-07/phone-admin-hq.png`, `phone-approvals-card.png`, `phone-settings-after-save.png`, `web-admin-hq-settings.png` (the black picture in the card shot is my 1-pixel test image).
- **Work page numbers:** paid hours (breaks out, overtime split by week) only; the hourly rate shows as a plain "$16.50/hr" setting, never as pay; salaried-only `expectedPay` is intact.
